# Contract — character-visual-development

## Runtime capability aliases
- `character_reference_package`
- `character_look_acceptance`

## Authoritative inputs
- Versioned source and upstream artifacts required by the procedure.
- Locked creative invariants plus relevant rights, consent and approval records.
- Applicable budget, schedule, jurisdiction, provider-policy, safety and quality constraints.

## Missing-input behavior
Fail closed for missing rights, consent, required human approval, authoritative version, locked-invariant context or a decision that would make the output misleading. Record ordinary optional omissions and continue only when the result remains valid.

## Output contract
Return structured, versioned results with `schema_version`, project/artifact identifiers, exact upstream version IDs, decisions/findings, evidence versus assumption labels, confidence where uncertain, provenance, downstream consumers, acceptance state and escalation owner.

## Failure taxonomy
- `missing_authoritative_input`
- `stale_or_conflicting_input`
- `rights_or_consent_block`
- `locked_invariant_conflict`
- `human_authority_boundary`
- `schema_or_quality_failure`
- `safety_or_jurisdiction_escalation`
- `budget_schedule_or_provider_block`

## Recovery
Repair locally when evidence supports it, preserve the superseded version, rerun only invalidated descendants and route consequential uncertainty to the accountable human. Never turn an unresolved dependency into an invented fact.

## Positive trigger example
Use this skill when the user or work order explicitly requests: Build production-grade character reference packages spanning identity, turnaround, expression, silhouette, scale and approved look continuity.

## Negative trigger example
Do not activate it merely because the project is audiovisual; do not bypass the responsible department, independent reviewer, specialist or human approval gate.

## Skill-specific decision rules
- A mood board is not a character reference package until identity and state are testable across views.
- Real-person likeness, protected designs and source references require documented rights and consent.
- Base identity and scene-specific state are versioned separately to prevent accidental canon drift.

## Skill-specific output shape
- character identity sheet
- turnaround and expression matrix
- scale and silhouette chart
- state/variant ledger
- reference bindings and acceptance rubric

## Skill-specific quality checks
- Views share consistent camera and neutral presentation.
- Every reference has provenance and usage status.
- Acceptance criteria cover identity and state separately.

## Handoff
character_director for canon, production_designer for visual-world fit, costume and hair/makeup teams for appearance states, generative_supervisor for provider binding and qc_supervisor for independent acceptance.

## Example
A lead character receives a neutral four-view sheet, eight expressions, height scale, posture rules and three separately versioned wardrobe/aging states with measurable face and silhouette tolerances.

## Counterexample
Bob saves one cinematic portrait as the canonical reference and assumes every provider can infer the character's profile, back, scale, costume changes and expressions.
